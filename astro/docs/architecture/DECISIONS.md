### PUB-01｜48 张原作派生场景 WebP 是否允许继续公开

**状态：PENDING；发布阻断候选，推荐默认排除。**

- 证据：公开 VN 分支当前跟踪 48 张 `source/images/ginka/scenes/*.webp`；`tools/build-scene-images.py` 明确从私有解包的 `cr_event` / `bgimage2` PNG 缩放生成；`astro/tools/prepare.mjs` 会复制跟踪的 `source/images` 到 Astro public staging。GitHub 仓库为 public，固定提交的 48 个 Raw URL 均可匿名读取；本轮核查的 `main` 与已知 GitHub Pages 部署不含该 scenes 路径，生产站点相应 48 个标准 URL 均为 404。没有发现这 48 项逐项公开再分发许可记录。
- 选项：
  - **A（推荐）**：先从公共构建路径排除这 48 张，使用自制/明确获许可的图像作公开 fallback；原作派生图只通过受限 localhost 私有预览使用。
  - **B**：提供可核验、覆盖派生加工及公开网站分发的权利许可后，按文件路径和 SHA-256 建立批准清单，再逐项加入公共构建。
- 影响：A 会改变公开 VN fallback 的视觉素材，但不应破坏文章/路由；B 在许可资料核实前不能作为 build/release 默认值。版权署名、WebP 转码、旧站曾发布其他图片都不等同于此批素材获许可。
- 暂行策略：已在 `prepare.mjs` 的任何清理/写入之前加入路径预检，实际运行证实这 48 张候选会被拒绝，且现有 public/.generated 保持原样；这只是短期范围守卫，不是完整许可 allowlist。未生成新 public/.generated/dist，不上传 artifact、不部署、不删除远端文件。需要用户决定是否移除既有公开开发分支的素材，或提供逐项许可；独立代码与源级测试继续推进。
